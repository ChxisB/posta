Um template é conteúdo de e-mail reutilizável (assunto, HTML e uma parte em
texto puro opcional) deixado pronto para a próxima
[transmissão](/pt-BR/concepts/broadcasts) ou envio pela API. Crie um no editor
de blocos do painel, com os mesmos campos de mesclagem por contato que as
transmissões usam, ou gerencie templates pela API. Escolher um template no editor da
transmissão copia o conteúdo dele como ponto de partida; editar o template
depois não altera aquela transmissão, e apagá-lo deixa todas as transmissões
intactas.

## Rascunhos, versões e tags

Um template é um rascunho de trabalho até você publicá-lo. Salvar pelo painel
ou por `PATCH /templates/{id}` altera só o rascunho. Publicar congela o
rascunho como a próxima versão numerada (1, 2, 3 e assim por diante), e uma
versão nunca muda depois disso.

```bash
curl -X POST https://api.posta.example/templates/welcome/publish \
  -H "Authorization: Bearer po_..." \
  -H "Content-Type: application/json" \
  -d '{ "tags": ["production"] }'
```

```json
{ "object": "template", "id": "7f5e...", "version": 3, "created": true, "tags": ["production"] }
```

- **Publicar é idempotente.** Se o assunto, o texto de pré-visualização, o html
  e o texto do rascunho já forem iguais aos da versão mais nova, nada novo é
  criado e essa versão volta com `created: false`. Renomear um template não
  conta como mudança.
- **Tags** são nomes como `production` ou `staging` que apontam para uma
  versão. `PUT /templates/{id}/tags/{name}` com `{ "version": 2 }` move uma tag,
  então o que a tag significa pode mudar sem mexer no código que envia. O nome
  de uma tag usa letras, dígitos, `.`, `_` ou `-`, começa com letra ou dígito,
  tem até 64 caracteres, diferencia maiúsculas de minúsculas e não pode ser só
  dígitos. Um template guarda até 20 tags e até 200 versões, e você pode definir
  até 5 tags em uma chamada de publicação.
- **Excluir** uma versão é recusado com `409 template_version_tagged` enquanto
  uma tag apontar para ela. Números de versão nunca são reutilizados.
- **Ler** o rascunho: `GET /templates/{id}` retorna o rascunho, com `status`
  `draft` até a primeira publicação e `published` depois, `version` e
  `published_at` da versão mais nova, `tags` e `has_unpublished_versions`, que
  é `true` enquanto o rascunho difere da versão mais nova.
  `GET /templates/{id}/versions` lista as versões e
  `GET /templates/{id}/versions/{version}` retorna uma com o conteúdo congelado.

No painel, o cabeçalho do editor mostra em que pé o template está: não
publicado, publicado como uma versão, ou uma versão mais alterações no
rascunho. **Publicar** salva suas edições e congela o rascunho como a próxima
versão. **Versões** lista cada versão com suas tags, define, move e remove
tags, exclui uma versão que não tem tag e carrega uma versão antiga no editor
como uma edição não salva, para você salvá-la como rascunho e publicá-la de novo.

Os templates que existiam antes do versionamento ganharam uma versão 1 com o
conteúdo da época, então já enviam.

## Enviar com um template

`POST /emails`, `POST /emails/batch` e `POST /broadcasts` aceitam uma
referência `template` no lugar de `html` e `text`:

```json
{
  "from": "Acme <hello@acme.dev>",
  "to": ["ada@example.com"],
  "template": {
    "id": "welcome",
    "tag": "production",
    "variables": { "FIRST_NAME": "Ada", "ORDER_ID": 1042 }
  }
}
```

- `id` é o id ou o alias do template.
- Informe no máximo um entre `version` e `tag`. Sem nenhum, vale a versão
  publicada mais nova. O rascunho nunca é enviado, então uma edição não
  publicada não chega a uma caixa de entrada por acidente.
- `template.variables` preenche os campos de mesclagem (`{{{FIRST_NAME}}}`,
  `{{{ORDER_ID}}}` e `{{{NAME|fallback}}}` para um valor padrão) em um envio.
  Os valores são strings ou números, as chaves usam letras, dígitos e `_`, e
  pode haver até 100. `EMAIL`, `FIRST_NAME` e `LAST_NAME` são buscados em
  `variables` como qualquer outro nome. Os valores entram com escape no html, e
  um valor em um `href` ou `src` precisa começar com `http://`, `https://` ou
  `mailto:`.
- O assunto do template vale, a menos que a requisição traga um `subject`
  próprio, que prevalece. Se nenhum dos dois existir, a requisição é `422`. O
  texto de pré-visualização da versão entra como a prévia da caixa de entrada.
- `template` não pode ser combinado com `html` ou `text`.
- Uma transmissão criada de um template copia o conteúdo daquela versão na
  criação e mantém os campos de mesclagem, então cada contato ainda recebe os
  próprios valores no envio. Ela não guarda vínculo com o template.

| Problema | Resposta |
| --- | --- |
| Template, versão ou tag não encontrados | `404 not_found` |
| O template não tem versão publicada | `422 template_not_published` |
| Nem a requisição nem o template têm assunto | `422 validation_error` |
| Mais de 200 versões ou 20 tags | `422 template_version_limit`, `422 template_tag_limit` |
| Excluir uma versão para a qual uma tag aponta | `409 template_version_tagged` |

O `templates.publish()` do SDK do Resend e o `templates.create(...).publish()`
funcionam como no Resend, e uma publicação sem corpo é aceita.

## Templates em HTML e o editor de blocos

Um template criado com `html` (pela API, pelo MCP ou por uma migração) é
escrito em HTML: o painel o abre na pré-visualização e o edita no modo
código (fonte ao lado de uma pré-visualização ao vivo), mantendo o HTML byte a
byte. O editor de blocos nunca o toca por conta própria, porque interpretar um
layout de tabelas e CSS inline como blocos o achata. Converter em blocos é uma
escolha explícita do usuário no painel: como uma cópia convertida
(`<name> (blocks)`, com o original intacto) ou no próprio template, caso em
que o HTML armazenado só muda na próxima gravação.

## Aliases

Um template pode ter um `alias`: letras, dígitos, `.`, `_` ou `-`,
começando com letra ou dígito, até 100 caracteres, sensível a maiúsculas e
único por equipe, e toda rota de template individual o aceita no lugar do id:
`GET`, `PATCH`, `DELETE /templates/{id-ou-alias}`, `/publish` e
`/duplicate`. Um alias já em uso é `409`, `"alias": null` no `PATCH` o
remove, e um alias não pode ter a forma de um UUID (ficaria inacessível, já
que UUIDs são resolvidos por id primeiro).

## API

- `POST /templates` com `{ name, html, subject?, text?, alias? }` →
  `{ "object": "template", "id": "..." }`.
- `GET /templates`: listagem com paginação por cursor;
  `GET /templates/{id-ou-alias}`: o corpo completo.
- `PATCH /templates/{id-ou-alias}`: qualquer um dos campos acima; `""` ou
  `null` limpa `subject` ou `text`. Escrever `html` ou `text` transforma um
  template criado no editor de blocos do painel em um de HTML puro (o
  documento de blocos do editor é descartado, já que ele regeneraria o
  conteúdo antigo no próximo salvamento pelo painel).
- `DELETE /templates/{id-ou-alias}`.
- `POST /templates/{id-ou-alias}/duplicate`: cria `<name> (copy)` com o
  mesmo conteúdo e sem alias.
- `POST /templates/{id-ou-alias}/publish`: congela o rascunho como a próxima
  versão, com `{ "tags": [...] }` opcional.
- `GET /templates/{id-ou-alias}/versions`,
  `GET` e `DELETE /templates/{id-ou-alias}/versions/{version}`.
- `GET /templates/{id-ou-alias}/tags`, e `PUT` e `DELETE`
  `/templates/{id-ou-alias}/tags/{name}`.

## Ainda não suportado

- `from`, `reply_to` e `variables` no próprio template: um valor na criação ou
  atualização é rejeitado com `422 <campo> is not supported on templates yet`
  em vez de descartado em silêncio; as leituras retornam `null`, `null` e `[]`.
  Coloque `from` e `reply_to` no envio ou na transmissão, e passe `template.variables`
  no envio.
- Restaurar uma versão para o rascunho é uma ação só do painel. Pela API, leia
  a versão e faça `PATCH` com os campos dela.
